### 持续关注的关键语义

1. 点击“查看关注范围”只打开确认；只有“确认开始关注”成功写入授权才启动。
2. 范围为指定文档全文，明确不沿用上次 Check 的局部选区。确认时对照已保存的标题、版本和正文，以该版本作为起点，不立即重复检查。
3. 读取的是本地已保存版本；500ms 轮询，版本稳定至少 750ms 才提交。处理中多次编辑合并到最新稳定版本，不承诺检查每次按键。
4. 同材料按 Web Lock 绑定一个发起页面；每关注串行处理、每版本最多一次提交。任务入队与 lastVersion 推进同事务。
5. 空白或超过 60,000 UTF-16 单元的版本注明跳过；下一有效版本继续。失败版本不自动无限重试。
6. 其他同源页面可以查看与停止，不能重复执行或自动接管。停止原子取消关联 queued/running 任务；迟到结果不能覆盖取消，已完成回信保留。
7. 关闭或刷新发起页面后，恢复时标为已中断。继续需要“重新确认关注”。关闭 Helpful proposals 只停止邀请，不撤销既有关注。
8. 自动关注 Check 不再生成新邀请。相同材料本页最多邀请一次，包含拒绝、取消、完成、过期及材料变化失效；刷新重建邀请会话，不恢复关注。

## 3. 技术方案与数据

前端采用 React 19、TypeScript、Vite、Zustand 5；IndexedDB 通过 idb 管理；普通本地处理使用领域函数，使魔任务通过 module Web Worker 执行。Web Locks 管理任务和关注的页面所有权；BroadcastChannel、focus 重读及轮询同步记录。Zustand 管理视图与运行状态，不是持久化数据库。样式为现有 CSS，素材复用用户原始图集。

后端为 Python/FastAPI 连通性骨架。依赖范围见根 package.json，实际锁定依赖见 package-lock.json 与 requirements.lock.txt。上一轮构建显示 Vite 6.4.4；Vitest 4.1.12，Playwright 使用已安装的 Chrome。不要无需求升级依赖。

| 数据类型 | 核心用途 |
| --- | --- |
| Material | 稳定 id、text/title、version、updatedAt，来源 virtual_document；编辑递增版本 |
| SelectionContext | materialId/version 与 UTF-16 半开区间 [start,end)，校验选区与原文一致 |
| MaterialSnapshot | 独立 id、来源 id/version/title、冻结文本、范围和捕获时间 |
| ActionDraft | understand/check/create/summon 入口、快照、要求、使魔、本次摘录长度 |
| LocalRecord | CheckRecord 或 TextRecord；含结果、来源快照、引用与处理参数 |
| JointDraft / JointRecord | 两份快照与独立来源结果；operation=joint；不是第四个基础能力 |
| Task | 快照、角色、operation、status、结果、未读、归档、错误；可选 watchId / excerptLimit |
| Watch | materialId/title、baseline 全文快照、lastVersion、active/stopped/interrupted、确认时间、提示 |
| Proposal 会话 | 偏好/联合/关注候选、共享展示时间及去重状态；非持久化用户行为档案 |

IndexedDB 名称仍为 `wisp-module-one`，**当前 schema v5**。仓库：materials、preferences、checks（名称沿用，保存直接三能力及联合结果）、tasks（回信嵌入任务）、watches（持续关注授权）。不要因数据库名称含 module-one 而重建或更名。

文档写入用 expectedVersion 在同事务检查，冲突保留内存草稿并提示复制后重新载入；不强行覆盖。正文保存防抖 350ms。只有落盘成功才显示“已保存”或未读回信。任务状态 queued → running → completed/failed；pending 可转 cancelled/interrupted，终态拒绝迟到完成。收好记录不删除结果。
